A fast viewer and editor for Markdown documents. Files are only modified when you save with Ctrl+S.

Opening documents

  • Double-click any .md file in File Explorer.
  • Drag a file onto the window.
  • Press Ctrl+O or use the folder button in the toolbar.

Documents open in tabs, in the toolbar. A file opened from outside while the app is running (a double-click, Open with, leggimi file.md) gets a new tab in the window you used last; if it is already open, its tab comes to the front. Inside the app, a click on a file, a recent document, a search result or a link opens it in the current tab; Ctrl+click (or the middle button) opens it in a new tab behind the current one, Ctrl+Shift+click in a new tab in front and Shift+click in a new window, as do Open in a new tab and Open in a new window in its right-click menu. Files opened with Ctrl+O or dragged onto the window get a tab each. A document is never open twice in the same window: opening it again brings its tab to the front.

A new tab starts on the start page, which lists the files you opened recently: click one to open it there. Every document also remembers where you stopped reading and scrolls back there when you open it again.

From a terminal, leggimi file.md opens a file and --line 40 opens it at that line (the leggimi command is available once the app is installed).

Tabs and windows

Ctrl+T, or the + after the last tab, opens a new tab, and Ctrl+Shift+N a new window. Ctrl+W closes the tab, as do its × and a middle click on it: closing the last document leaves the start page, and Ctrl+W on a lone start page closes the window. Ctrl+Shift+W closes the window with all its tabs, and Ctrl+Shift+T reopens the last tab you closed. A tab with unsaved changes asks before it closes: Save, Don't save or Cancel; closing the window asks once, listing the documents with unsaved changes.

Ctrl+Tab, Ctrl+1 … 9 and the other tab keys under Keyboard shortcuts switch tabs from the keyboard. Each tab keeps its own reading position, edits and undo, Back / Forward history and file browser folder. Point at a tab to see its folder and reading time; when the tabs run out of room, the arrow at the end of the strip lists them all. Right-click a tab for Move to a new window, Close other tabs, Close tabs to the right, Copy path and Show in File Explorer.

Drag a tab along the strip to reorder it (Esc puts it back). Pull it off the strip and it opens in a window of its own, which follows the pointer; drop it on another Leggimi window's tabs and it moves there, unsaved edits and undo included. Dragging the only tab of a window moves the whole window, and dropping it on another window's tabs merges the two.

The toolbar is also the window's title bar, in the colours of the theme: drag its empty part to move the window, double-click it to maximize or restore the window, and point at the maximize button for the snap layouts of Windows 11.

A thin bar along the top of the document shows how far you are; point at the document's tab to see the estimated reading time.

Ctrl+C on a selection copies it with its formatting, ready for Word or Outlook, as well as plain text. The document can also be dragged like a sheet of paper: with the middle mouse button anywhere, or with the left button on the empty space beside the text.

Right-click the document, or press Shift+F10 or the menu key, for its menu: copy the selection (with its formatting or as plain text) or search for it in the document or the folder; open or copy a link; open an image, a diagram or a table with Open preview, copy a code block or a table; Copy link to this section gives [Heading](file.md#heading), a link that works from any other document and on GitHub too; Edit from here opens the editor at that point; Copy the whole document copies it with its formatting, as Ctrl+Shift+C does; print or save as PDF.

Like in a browser, Alt+← (or the mouse's side back button) returns to where you were before a link to a section, a click in the outline or a move to another document; Alt+→ (or the forward button) goes forward again. Back and Forward are also at the top of the right-click menu. Each tab has its own history.

Editing

Press Ctrl+E or the pencil button (Edit) to edit the open document: the text editor appears on the left, with a live preview on the right. While you edit, the button shows an open book: Back to reading. In a window narrower than about 760 pixels only the editor shows; the preview comes back when the window is wider or when you go back to reading.

An orange dot on the document's tab, in place of its ×, marks unsaved changes — save with Ctrl+S, and the dot turns into a check for a moment (screen readers hear "Saved"). Leaving edit mode or opening another document with unsaved changes asks for confirmation first. If the file changes on disk while you have unsaved edits, a warning appears instead of overwriting your work, and saving over a file that changed since you opened it asks before overwriting it.

While editing, a double-click on the preview puts the editor's cursor on that word, and the preview stays where it is; while reading, a double-click selects a word as usual.

Formatting: the bar above the editor formats the selection — or the word under the cursor — and inserts tables, Mermaid diagrams, formulas and callouts. Type / at the start of a line to pick a block by name. Pasting a link over selected text turns it into a Markdown link.

Tools (the sliders button at the right of the bar) collects find & replace, the line commands, Comment line and Spellcheck. Comment line (Ctrl+/, that is Ctrl with the keys that type /: Ctrl+Shift+7 on Italian and German keyboards) wraps the lines in <!-- -->, so they are hidden when reading; inside a code block it uses that language's comment, and a second time it takes the comment away. Spellcheck underlines misspelled words with the dictionary of the interface language, with suggestions on a right-click (after a language change in the reading settings, from the next start).

Tab indents. To leave the editor with the keyboard, press Esc and then Tab within two seconds; if text is selected or a panel (such as find & replace) or a menu is open, press Esc twice first.

Recovery: while you have unsaved changes, a copy of the text is kept aside. If the app is closed without saving (a crash, a forced shutdown), the next time you open that file a notice offers to restore it. The file itself is never touched until you save.

Images: paste a screenshot (Ctrl+V) or drop an image file into the editor — it is saved to an assets folder next to the document and linked with a relative path.

Browsing files

The left panel lists the Markdown files in the folder you opened, up to four levels of subfolders. Opening a file from the panel keeps the same root folder, so you never lose your place; use the up arrow next to Files to move the root to the parent folder. Opening a document from outside the current folder re-roots the panel there. Folders you collapse stay collapsed while you navigate — and across restarts.

Folders without Markdown files are hidden, as are hidden and build folders such as node_modules.

The pane updates by itself when files are added, renamed or deleted in the folder. Rename the open document and the window follows it; delete or move it and its text stays on screen, with a notice offering Save again.

From the keyboard the list works as a tree: ↑ / ↓ move, → opens a folder or steps into it, ← closes it or goes up to its parent, Home / End reach the ends, Enter or Space opens, and Ctrl+Enter opens in a new tab.

Both side panels can be widened by dragging their inner edge — double-click the edge to restore the default width. Their text size follows Panels in the reading settings.

A window can be as narrow as 480 pixels: half a laptop screen, or a Windows 11 snap layout. When the window gets narrow, the outline and then the file browser fold away by themselves; their toolbar buttons (or Ctrl+I and Ctrl+B) then open them over the text, and Esc, a click elsewhere or a pick puts them away again.

The search box above the tree (Ctrl+Shift+F) finds text in every Markdown file of the folder — matches show the file and a snippet, and opening one highlights the term in the document. Esc clears the search and brings the tree back.

Outline

The right panel lists the document headings and highlights the one you are reading. Click any entry to jump to it. On long documents a filter box appears above the list: type to narrow the headings, then ↑ / ↓ and Enter jump to one; Esc clears it.

After a jump — from the outline, a link to a section, the . / , keys or --line — the heading or block you land on lights up for a moment, so your eye finds it. Back and Forward do not light it up.

Live reload

Open files are watched on disk. When one changes, the view refreshes automatically and keeps your reading position — useful while a document is being regenerated; a tab in the background catches up when you return to it. In edit mode the refresh only happens while your buffer has no unsaved changes.

F5 or Ctrl+R reads the file again on request, keeping your place; with unsaved edits it does nothing.

Rendering

  • GitHub-flavored Markdown: tables, task lists, strikethrough, autolinks. Web addresses become links, those starting with www. too, as on GitHub; file names such as README.md stay text.
  • Code blocks are syntax-highlighted and have a copy button on hover.
  • mermaid code fences render as diagrams; invalid syntax falls back to the code block with an error note.
  • A table or a diagram wider than the reading column widens up to the whole width available, centred: no sideways scrolling, and the diagram's text keeps its size.
  • Click a diagram or an image to open it full-window: + / − or the scroll wheel zoom, dragging pans and Esc closes. Fit (0) fits it to the window, Width (W) fits its width, starting from the top, and 100% (1) shows it at its actual size. The copy button offers the image as PNG (normal or large), a diagram also as SVG, and both can be saved to a file.
  • Math renders with KaTeX: $…$ inline, $$…$$ or a math code fence for display blocks.
  • GitHub-style callouts: a quote starting with [!NOTE], [!TIP], [!IMPORTANT], [!WARNING] or [!CAUTION].
  • Footnotes: [^1] in the text and [^1]: … anywhere; the notes are collected at the end, with links there and back.
  • Task lists are live: clicking a checkbox updates the [ ] / [x] in the file right away (with an Undo in the notice), or in the editor buffer while you are editing. Only the box ticks the task: clicking or double-clicking its text, to select a word, changes nothing.
  • Tables have two buttons at the top right, shown on hover or when you reach them with the keyboard: Copy table (for Excel) puts the table on the clipboard as tab-separated text, ready for Excel or Google Sheets, and Open preview shows it full-window, across the window's width (also from the right-click menu).
  • Links to other documents work like a wiki: [text](other) finds other.md, [text](folder/) opens the folder's index.md or README.md, and other.md#section jumps to that heading. Headings get the same anchors as on GitHub (## 1. Introduction → #1-introduction), so tables of contents written for GitHub or by an AI assistant work here too; links written for earlier versions still land.
  • YAML front matter between --- lines is folded into a Front matter block at the top: click it to see the fields as a table.
  • A paragraph containing only [TOC] becomes a table of contents of the headings that follow, which also goes to print, HTML and DOCX.
  • Images with relative paths resolve against the document's folder. Logos made for GitHub's light and dark themes (marked #gh-dark-mode-only / #gh-light-mode-only, or a <picture> with light and dark sources) show the one for Leggimi's theme; printing and exports use the light one.
  • Links to web pages open in your default browser, mailto: links in your mail app; links to other Markdown files open in the viewer, to images in the preview, to a folder in the file browser. A link to any other file (a PDF, a spreadsheet) offers to open it in its own app.
  • Simple HTML in the text works: <br>, <kbd>, <sup>, <details>, images (<picture> and srcset too), video and audio from the document's folder. As on GitHub, a tag that is not HTML, such as <name>, does not show: to show it, write it between backticks (`<name>`) or with a backslash in front (\<name>). Tags that would change the page, such as <style>, <script>, <title> and <iframe>, show as text.

Sharing and export

The Share button (Ctrl+Shift+E) collects everything that leaves the app:

  • Copy as rich text (Ctrl+Shift+C): puts the rendered document on the clipboard with formatting, ready to paste into Outlook, Word or Teams. Local images are embedded.
  • Print… (Ctrl+P): prints only the document, laid out for paper, always on a light background, with the title and date at the top of every page and "page / pages" at the bottom; a table wider than the page is scaled down to fit it.
  • Save as PDF: the same layout written straight to a PDF file, no dialog other than the file picker. New page at every heading 1 is an option in the menu, remembered, for both.
  • Export as HTML / DOCX: saves the document as a single self-contained .html page that opens in any browser, or as a .docx optimized for Microsoft Word — math becomes native Word equations, diagrams become images.

Printing and exports always use the standard text layout, whatever reading settings are active.

Reading settings

The Aa button opens the reading settings: text size, sans or serif font, line spacing, column width, the interface language and the theme: light, sepia (warm paper), dark, black (for OLED screens) or auto (light or dark following Windows). Text size is also available anywhere with Ctrl+= / Ctrl+−, Ctrl+scroll wheel, and Ctrl+0 to reset; the editor text scales along with it. Panels sets the text size of the file browser and the outline on its own — Ctrl+scroll wheel over a panel changes that one instead. Every choice is remembered across restarts.

With Windows' Animation effects turned off (Settings > Accessibility > Visual effects), scrolling jumps instead of gliding and the highlight after a jump does not animate.

Windows integration

Files you open are added to Windows' Recent items and to the app's taskbar jump list. Double-clicking any .md file in File Explorer opens it here once the association is registered by the installer.

In File Explorer, New → Markdown document (right-click in a folder) creates an empty .md file. With the installer, that name — and the name of the file type in Explorer's Type column — follows the Windows display language (Documento Markdown on an Italian Windows); in the Microsoft Store version the entry is always Markdown document.

Right-click a file in the browser panel for Open in a new tab, Open in a new window, Show in File Explorer, Copy path or Copy as Markdown link (relative to the open document). The pin button keeps the window on top of the others; it no longer has a shortcut, since Ctrl+Shift+T now reopens the last closed tab.

In the Microsoft Store version, after a few days of use a small card asks Enjoying Leggimi?: Rate opens the Store's rating dialog over Leggimi (or the Store page, if the dialog cannot open), Later asks again in a month and No thanks never again. The card shows in one window at a time and, left unanswered, waits a week before coming back; Rate on the Store, at the bottom of this help, does the same as Rate.

A portable build is available on GitHub as a zip: unpack it anywhere and run it, and it keeps its settings in a data folder next to the program instead of your profile.
